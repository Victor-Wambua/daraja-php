3What happened

    How this demo works

    The PHP library is not running in this page. This is a JavaScript port of its pure parts, checked against the real PHP code. I did not try PHP compiled to WebAssembly: the mock server needs SQLite, cURL and a separate worker process, so it would not have run without changing the library.

    Ported from the library

    • Phone normalisation, whole-shilling amounts and request validation, with the library's error messages.
    • The East Africa Time timestamp and the base64 Password.
    • The exact OAuth and STK requests, headers and JSON bodies, and the token cache.
    • The strict callback parser, the result code mapping and the amount and phone cross-check.
    • The idempotency state machine behind CallbackProcessor.
    • The mock server's validation, error bodies, bearer tokens, callback bodies and retry schedule.

    Simulated here

    • The network: a request is a function call.
    • The phone and the customer: you choose the answer.
    • The clock: it starts at your device time and jumps over waits.
    • Ids and receipts: invented from a seeded generator.
    • The shop that owns the order: a small in-memory port of examples/plain-php.
    • Three scenarios the mock cannot produce on its own (marked in the list): a callback that overtakes your app, a stale cancel after a success, and a changed amount. The demo injects them.

    Not shown

    • C2B, B2C, Transaction Status and Reversal.
    • The source IP allow-list and the SQLite idempotency store with its UNIQUE receipt lock.
    • Early token refresh and the Laravel snippets.
    • The mock's own web console with the simulated phone.

    How the port is kept honest. demo/tools/golden.php runs a set of inputs through the real PHP code, including the real client talking to the real mock in process, and writes the answers to demo/test/golden.json. The port must reproduce them exactly. CI fails if the PHP library changes and the file is not regenerated, or if the port disagrees.

    What is not verified. Like the library, this demo has never been run against Safaricom's sandbox or live API. It shows how daraja-php behaves against its own mock, not how Daraja behaves. Request and callback shapes follow Safaricom's public documentation.

    Your data. Nothing leaves the page. The form values are saved in this browser's local storage so a reload keeps them. After the first load the page also works offline.

    PHP snippets

    These are cut word for word from the examples/plain-php app in the repository. A script re-cuts them in CI and fails if the example changed, so the page cannot show stale code.

    Run the real thing

    Needs PHP 8.3 or newer with curl and pdo_sqlite, and Composer. Nothing needs the internet except composer install.

    Open the shop, press Pay now, then answer the prompt on the phone in the console. Tick Lose the callback first to practise the STK query path, or press Redeliver (duplicate) to check the order is credited once.
